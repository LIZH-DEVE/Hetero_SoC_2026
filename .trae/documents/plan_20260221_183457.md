## SM4字节序问题修复计划

### 问题分析

通过测试发现SM4加密结果与标准值不匹配，但存在字节序反转特征：

* `result_31 = 4ef09779cd384903f2298f31abee7cb0`

* 实际输出 = `abee7cb0f2298f31cd3849034ef09779` (32位字序反转)

### 根本原因

在`sm4_encdec.v`第260-261行：

```verilog
assign { word_0, word_1, word_2, word_3} = result_31;
assign reversed_result_31 = {word_3, word_2, word_1, word_0};
```

这个反转操作是正确的（SM4标准要求最后反转），但问题在于：

1. 轮密钥的字节序可能与数据不匹配
2. 输入数据的字节序处理可能有问题

### 修复步骤

1. **检查轮密钥字节序** - 验证`key_expansion.v`生成的轮密钥是否正确
2. **检查数据输入字节序** - 确保`data_in`的字节序与算法预期一致
3. **修复字节序问题** - 根据分析结果修复相关模块
4. **运行测试验证** - 使用标准测试向量验证修复结果
